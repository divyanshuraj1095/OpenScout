# Target architecture

One Maven application under backend/, Java 21. Separate packages for identity, repositories, issues, bookmarks, indexing, retrieval, chat and preferences. Each owns its controllers, transactional services, persistence and DTOs. Controllers accept validated inputs and obtain the principal from Spring Security. Services enforce membership before reads, writes, cache lookups and provider spend.

Use a stable Spring Boot 4.0.10 release with Spring AI BOM 2.0.2. Resolve and pin a supported GA patch and Maven wrapper in Phase 1, record effective POM, compile and run a context test on JDK 21 before accepting the pair. Boot manages Security, JPA/Hibernate, JDBC and Micrometer versions. Spring AI supplies replaceable embedding adapters. [Spring AI compatibility](https://docs.spring.io/spring-ai/reference/2.0/getting-started.html)

PostgreSQL provides transactions and durable job state. Flyway owns DDL and Hibernate validates it. pgvector enables an explicit parameterized distance query alongside relational authorization. Redis later handles expendable caches and atomic rate limits. GitHub REST supplies public source and issue metadata. Groq generates answers. Ollama serves local embeddings, with a configurable hosted adapter in production.

**Ingestion.** IndexService resolves a public repository and immutable commit, then enqueues a durable job. Workers claim eligible rows with SKIP LOCKED in short transactions. Bound worker count, provider batches, repository bytes, file sizes and tokens. Enumerate complete trees or fail on truncation. Skip binaries, generated/vendor files, secrets, symlinks and submodules. Split UTF-8 text at line boundaries with bounded overlap. Reuse matching content/chunker/model revisions, recording fresh path and line provenance. Exclude deleted paths from the new manifest. Commit batches idempotently. Retry transient failures with jitter, Retry-After and an attempt cap. Reclaim expired leases with fencing tokens. Promote the complete generation by compare-and-swap in one transaction. Readers retain their pinned generation until finished.

**Retrieval.** RetrievalService checks membership and public visibility, pins the active index, embeds the question using its exact model, and selects top-k chunks constrained by repository and version before ranking. PromptBuilder separates instructions, question and quoted untrusted chunks with opaque IDs. No tools, command execution or document-directed actions. Bound input/output tokens. Accept only citation IDs present in this retrieval result. Build commit-pinned links and line ranges server-side. Abstain on weak evidence or invalid citations. Apply the same process to issue explanations and owner-scoped chat history.

**Operations and cost.** Start with one long-lived process and bounded background workers. Compose targets local or single-host operation with persistent volumes, HTTPS ingress, secret injection and tested backups. Ephemeral/serverless hosts cannot guarantee durable workers or local Ollama capacity. Confirm managed Postgres permits pgvector and reserve disk for concurrent generations. Recheck public visibility before serving indexed data and fail closed on unknown visibility. Send only necessary passages to hosted providers. Keep logs free of cookies, prompts and keys. Micrometer exposes latency, queue age, provider failures and token counts privately to Prometheus; Grafana visualizes them.

Student budget: target $0 incremental service spend on existing local hardware. Electricity and network usage vary. Use Compose for Postgres/pgvector, Redis, Ollama, Prometheus and Grafana as their phases arrive. Require explicit approval for paid resources. Free hosts may sleep or interrupt workers. Plan lease recovery, provider quota backoff and storage headroom for two vector generations. Capacity-test before offering persistent indexing.
Use one public HTTPS origin with a trusted /api reverse proxy from Vercel to Render. Keep Set-Cookie host-only, bypass shared caching and forward Cookie, Origin, CSRF headers and Set-Cookie intact. Direct vercel.app to onrender.com cookies are third-party and may be blocked even with SameSite=None, Secure and credentialed CORS. Alternatively use same-site custom HTTPS subdomains and exact CORS. Verify login, CSRF, expiry and logout in browsers that block third-party cookies before release. See https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies


## Phase 4 implementation

The Spring process runs two polling lanes by default. Each lane claims one PostgreSQL job, fetches anonymous GitHub data by numeric repository ID and persists isolated staging rows. Readers pin a compatible active version by UUID. Promotion and job completion share one transaction. The packaged sample and its fixed-source endpoints continue using their original tables.
