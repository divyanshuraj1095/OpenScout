# Phase 4 · Asynchronous public repository indexing

## Request and publication lifecycle

A signed-in member with a current catalog visibility check posts to the repository's indexes route. IndexController checks membership and makes a fresh upstream public-identity check. IndexQueue.enqueue selects the membership again in the INSERT. Its ON CONFLICT predicate matches the partial unique index over queued, running and retrying jobs. Competing requests return the same UUID; only the active job creator supplies the requester identity for worker authorization. A request after terminal completion starts a new refresh. GET jobs/{id} checks current visibility and selects progress by both membership and repository ID. No indexing or embedding happens on the request thread.

IndexScheduler.start schedules a fixed number of serial polling loops. The default is two, with one to eight permitted. The executor has one recurring task per lane and stores no repository backlog in memory. IndexScheduler.stop interrupts the executor on shutdown. IndexWorker.poll claims one eligible row and starts a renewal task, executes it, classifies failures, then cancels renewal. stopHeartbeat shuts down the separate timer. PostgreSQL owns the backlog and recovery state across restarts.

IndexQueue.claim uses one UPDATE with a SELECT ... FOR UPDATE SKIP LOCKED CTE. It chooses a ready queued/retrying job or an expired running one and increments its monotonic fence. The claim statement commits before processing. IndexQueue.guarded begins a short transaction, conditionally updates the lease on the same job ID and fence while its running lease remains valid, and executes a local mutation under that row lock. Zero affected rows rejects the old owner. A 20-second renewal interval extends the deadline to 90 seconds. An expired owner cannot revive its own lease. Retryable IO, rate limiting and upstream service failures enter retrying; bounded exponential delay with jitter respects a longer server delay. Four processing attempts are allowed. Terminal failure clears the lease and deletes invisible staging data in the same transaction. Unsupported inputs and budget violations fail closed.

IndexWorker.check verifies requester membership around a fresh GitHub public-repository check. IndexWorker.process resolves HEAD on its first attempt, stores the immutable commit before walking the tree and reuses that pin on retry. The worker records the prior active UUID for compare-and-swap. Restarting a failed attempt rebuilds only this job's private staging version. It may repeat already-issued network calls. An idempotent database outcome does not imply exactly-once provider billing. All GitHub and model calls run outside database transactions.

## Snapshot and embedding decisions

IndexSource.head resolves a commit using a fixed GitHub API origin and a stable numeric ID. IndexSource.get issues anonymous, nonredirecting GETs, limits time and response bytes and treats unrecognized success shapes as unsafe. retryAfter handles delta seconds and HTTP dates. A recursive Git tree gives a single bounded manifest. files rejects truncated or incomplete results; get rejects an unexpected next-page link. This phase deliberately fails an oversized tree instead of publishing an incomplete traversal. Only regular non-executable blobs with supported paths are eligible. Symlinks, submodules, common build/vendor directories and secret-like paths are excluded. content reads a pinned blob, verifies encoding, byte count and Git blob SHA, decodes strict UTF-8 and filters binary controls and recognizable credentials. Downloaded text is never executed.

split creates inclusive, one-based source spans. Each chunk is bounded by UTF-8 bytes, preserves line boundaries and repeats the configured number of lines where possible. Oversized single lines fail the attempt. The version string includes the chunker algorithm, size and overlap. SHA-256 over normalized chunk text identifies reusable content. The input byte budget conservatively limits token consumption, including a prefix allowance. Operators can configure max-files (100), max-file-bytes (65,536), max-bytes (1 MiB), max-chunks (512), max-input-tokens (262,144), max-provider-calls (512), chunk-bytes (1,536), overlap-lines (1), batch-size (8, bounded to 64), incremental and workers under the index property prefix. Budget limits apply per attempt. Process-level concurrency multiplies them.

For a compatible active generation, the worker looks up the Git blob SHA within the same repository. Unchanged blobs copy stored vectors to the new path and line positions, including when the file moved. Changed files are fetched and rechunked. Matching prior SHA-256 **and** text can reuse a vector at a different line number. Other passages enter a bounded list for embedding. Encoder.batch has a sequential fallback; SpringEncoder advertises native batching through Spring AI EmbeddingModel.embed(List). Inputs retain the established document prefix. The pipeline checks response cardinality, dimension, finiteness and nonzero magnitude. insertFile and write persist immutable provenance. A complete snapshot supplies the new manifest; absent old paths have no rows in the replacement.

## Schema, promotion and retrieval

Flyway V5 is additive. indexing_jobs stores requester, repository, state, attempt fence, lease expiry, next eligible time, counts and safe error code. repository_indexes uses (repository_id,version) as its primary key, links to its job, and stores commit, embedding space, chunker and dimensions. A partial unique index enforces a single active generation per repository. repository_files records path, immutable blob hash and size. repository_vectors adds line span, chunk hash, source text and vector(768), with a composite foreign key through file to generation. The database can reject incompatible vector dimensions independently of Java. Original sample rows remain in rag_sample_chunks.

Promotion takes the fenced job lock, rechecks membership and stored vector count, compares the observed active generation to the expected base, retires the old version, activates the new one and marks the job succeeded only when manifest progress is complete. Any failed condition rolls the transaction back. Other readers see either committed generation. A stale worker cannot clear another worker's staging or publish progress after losing its fence.

SampleRag.askIndexed authorizes the caller, pins one active compatible UUID and commit, embeds the question and executes a membership-scoped exact cosine query over that UUID. SampleRag.answer and validate share the Phase 3 prompt, threshold, live visibility checks, citation validation and abstention behavior with the original sample. Citations use a server-built repository URL, pinned SHA, path and line span. Untrusted passages can contain false claims or hostile instructions; outputs remain untrusted. The fixture results from Phase 3 still apply to the assessment of local generator quality. Indexing correctness alone makes no answer-quality claim.

## Operations and limitations

- Failed staging rows are removed on terminal failure. Retried attempts restart their private version. Retired successful generations and terminal job history are retained so pinned requests and audits remain valid. There is no automatic retired-generation deletion or disk quota. Provision storage and develop a reader-aware retention policy before production.
- Source filters are conservative heuristics. They cannot recognize arbitrary credentials embedded in otherwise ordinary prose or code. Anonymous GitHub reads, fresh visibility checks and local Ollama minimize exposure. The current implementation supports a bounded subset of text files and ASCII paths. Oversized eligible files fail the generation.
- Anonymous GitHub quota limits real workloads. Actual provider operations can repeat after crashes. Health and latency measurements here use disposable local infrastructure. Multi-process deployments multiply configured worker counts. The read-before-publish visibility check cannot eliminate a subsequent upstream change; retrieval rechecks independently before disclosure.
- A catalog refresh can be necessary after its five-minute membership-visible freshness window. Old commit URLs can require GitHub redirects after a repository rename. A model revision label is operator supplied; changing deployed weights requires changing that label and reindexing.
- The asynchronous index and active-generation question endpoint constitute this phase. Durable chat history, Redis, frontend changes and production cutover are separate review gates.
